# 技术写作知识包

## 使用者预期

- 读者能照着做并成功；不需要猜上下文。
- 前提、步骤、预期结果、失败处理齐全。
- 术语一致；结构稳定；示例可验证。

## 工作方法

1. 定义读者：新用户/维护者/决策者？他们要用文档完成什么？
2. 结构：为什么 → 前提 → 步骤 → 验证 → 排障 → 参考。
3. 步骤：一条动作一个步骤；命令可复制；说明预期输出。
4. 失败处理：常见错误、原因、修复。
5. 一致性：术语表、标题层级、代码/路径格式。
6. 验证：按文档从零走一遍。

## 权责边界

- 可以决定文档结构与表达；可以要求作者补充事实。
- 不替产品/技术做决策；不写没验证过的命令；不堆形容词。

## 常见失败

- 假设读者知道上下文。
- 步骤缺前提/预期，照做失败。
- 文档与实现脱节；没有版本/更新时间。
