## 环境落地

重启 Windows 后 WSL 自动补装了 WSL 3.0.5（内核 6.18.58.1-1），然后按 12 号文档执行：

1. `wsl --import agentim D:\WSL\agentim D:\Install\WSL\ubuntu-base-24.04.4-base-amd64.tar.gz --version 2` —— 一次成功，VHDX 在 D 盘。
2. Tuwunel v2.0.0 deb：GitHub 直连被 reset；用 `https://gh-proxy.com/<github url>` 下载，53,655,342 字节，`file` 识别为 Debian 包。
3. `apt-get update && apt-get install -y ca-certificates`；`dpkg-deb -x` 到 `/opt/tuwunel`。
   - **二进制实际在 `/opt/tuwunel/usr/sbin/tuwunel`**（12 号文档原写 `usr/bin`，已订正）。
4. 写 `/etc/tuwunel/tuwunel.toml`（`server_name=localhost`、`127.0.0.1:8008`、注册 token、federation 关），`nohup` 启动。
5. Windows 侧 `curl http://127.0.0.1:8008/_matrix/client/versions` 返回 JSON —— WSL localhost 转发正常，不需要 portproxy。
6. `npm run setup-matrix -- --registration-token ...` 一次成功：三个用户、群、DM 全部建好；重复执行走登录 + 复用房间。

## E2E 结果

真实 Claude CLI + 真实 Tuwunel，验收 §9 五条：

- 群 @claude-dev：Claude 回复（`@script-peer`）→ peer 回复 → Claude 收到后 `PASS` → quiescent。
- DM：不 @ 也唤醒（2 人房间自动 direct）。
- 群里不 @：只有 inbound，不唤醒。
- 停机重启：state 载入 `processed=6`，只处理停机期间那条，旧消息不重跑，Claude session 继续 resume。
- 两个线程都在 `quietWindowMs` 后 quiescent。

独立核对：用 Matrix API `getMessages` 直接读房间时间线，确认人类/Claude/peer 的消息都在 homeserver 上，且 `m.mentions` 正确。

## 观察到的小事

- 人类一条消息同时 @ 两个 agent 时，两个 agent 并行回复；script peer 回的是人类，不是 Claude。要测 agent→agent 链，人类只 @ 第一个 agent，让它自己 @ 第二个（本轮已按这个方式验证）。
- 网关自己的 `[gateway] quiescent` 日志是判断收敛的可靠信号；audit.jsonl 里有完整 inbound/outbound/usage。
- 从 Git Bash 调 `wsl ... bash -c '...$VAR...'` 时变量会被外层吃掉，改用 `bash -s <<'EOF'`。这是工具链怪癖，不影响 PowerShell 里的正常命令。
