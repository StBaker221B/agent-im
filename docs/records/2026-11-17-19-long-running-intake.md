# 2026-11-17-19 长期驻守与需求 intake（v0）

- 记录时间：2026-11-17 下午。
- 触发：用户说明初衷是“多个 agent 长期驻守、重启后恢复”，一人公司/稳定业务流；一次性任务不需要整个团队；后续需要“人提问题 → 分析 → 推荐单点还是小团队”。
- 关联：[00 合同 §16.2](../00-requirements-contract.md) · [16 长期驻守与 intake](../16-long-running-and-intake.md) · [13 MVP 架构](../13-mvp-architecture.md)

## 需求已记录

正式需求写到 [16-long-running-and-intake.md](../16-long-running-and-intake.md)，并补进 00 合同 §16.2：

- 驻留/恢复：agent、房间、状态、未完成工作、session；
- 长期任务：任务台账、检查点、暂停/恢复、定时/触发、预算告警；
- intake：重述问题→推荐 single/pair/squad→角色/成本/风险/最小验证→人类批准；
- 默认优先单点，不为了热闹组队。

## v0 实现

- `POST /api/intake {problem}`：
  - 确保存在一个 `@intake`「需求顾问」（facilitator 模板、tools off、持久化）；
  - 复用/创建与人类的 DM；
  - 发送结构化评估 prompt；
  - 返回 room，UI 打开。
- intake prompt 要求输出：
  1. 问题重述与验收；2. 选项与推荐；3. 理由与风险；4. 团队角色（若推荐）；5. 最小下一步；最后一行 `RECOMMEND: single|pair|squad`。
- UI：Agents 页「评估需求」→ modal 输入问题 → 打开需求顾问 DM。
- 默认不自动建团队；人类看完建议后自己决定。

## 实测

问题：长期个人记账服务，自动整理账单/预算建议/问答，问单点还是小团队。

- 需求顾问返回：**推荐 single**；理由是没有并行收益、专业差异浅、财务正确性应靠确定性代码；pair/squad 只增加状态同步/权限/调试面；给 2 周最小验证。
- 末行 `RECOMMEND: single`。
- 重启 app 后：`@intake` agent、DM、2 条消息都还在，5 秒后仍是 2 条，没有重复回复。
- 这一轮只花了需求顾问 1 个 turn，没有创建团队。

## 现状边界

- 建议是自由文本 + 标签，UI 还没解析标签并一键转成“单 agent/小队”。
- 没有长期任务台账/调度/检查点/未完成 turn 恢复；重启能恢复 agent/房间/session，但进行中的 turn 仍会丢（设计上不重跑以免重复）。
- intake agent 和普通 agent 一样可暂停/删除；删除后再次调用会创建新的 `intake-*`。
- 没有“无人值守自治上限”（预算/审批/白名单）设计。

## 下一步

1. UI 解析 `RECOMMEND`，展示“按建议创建 single/pair/squad”按钮，人类确认后执行。
2. 任务台账（持久化）+ 重启后待办/进行中状态 + 定时/触发。
3. 常驻团队的值班/待命策略，避免每条消息唤醒所有人。
4. 长期运行的成本/失败告警与人类升级。
