# 2026-11-18-29 全局硬 kill / 恢复

- 记录时间：2026-11-18 凌晨。
- 目标：补合同 M7 的硬 kill；之前只有 per-agent/全局软暂停。
- 关联：[13 MVP 架构](../13-mvp-architecture.md) · [18 运维](../18-operations.md) · [记录 20 全局暂停](2026-11-17-20-activity-and-global-pause.md)

## 行为

- `POST /api/admin/kill {kill:true}`：
  - 所有非 deleted agent 置 `paused`；
  - `host.kill()`：停止 gateway sync、清空队列等待、关闭所有 runtime；
  - `/api/health` 的 `running:false`、`killed:true`；
  - 消息仍可写入 Matrix，但不会被 agent 消费，直到恢复。
- `{kill:false}`：
  - 清 killed；所有非 deleted agent 置 active；
  - 重建 runtime，`gateway.start()` 重新 sync；
  - 停机期间的消息按 Matrix since 补消费（不重复已处理 id）。
- UI：全局设置「硬 kill（停止 sync/runtime）」/「从硬 kill 恢复」；bootstrap 带 `killed`。
- 与软暂停区别：软暂停只让下一轮 PASS；硬 kill 停 sync/runtime。

## 实测

- health before：running=true, killed=false。
- kill=true：running=false, killed=true；bootstrap 12 个 agent 全部 paused。
- kill=false：running=true, killed=false；paused=0。
- 无模型调用。

## 边界

- 硬 kill 不杀 app 进程/Tuwunel；只是 gateway/runtime 停。
- 当前 turn 可能被中断；没有 turn 级恢复。
- 恢复会激活所有非 deleted agent，包括之前手动暂停的。
- 没有把 killed 持久化；app 重启后默认运行（agents 仍是 paused 状态）。
- 没有“只 kill 某个房间/某个 agent”的硬隔离。
