# 2026-11-18-41 消息 Reaction

- 记录时间：2026-11-18。
- 目标：C 轨道补最小的消息 reaction（先 👍）。
- 关联：[13 MVP 架构](../13-mvp-architecture.md) · [记录 39 分页](2026-11-18-39-history-pagination.md)

## 实现

- MatrixClient：
  - `sendReaction(roomId,eventId,key)` → `m.reaction`，`m.relates_to={rel_type:"m.annotation",event_id,key}`。
  - `#normalize` 识别 `m.reaction`，返回 `kind:"reaction", targetId,key,sender`。
  - Gateway `#ingest` 跳过 reaction，不让它进入 engine/wake。
- Server：
  - `roomMessagesPage` 从消息页里分离 reactions，返回 `{messages,reactions:{targetId:[{key,sender}]},next}`。
  - `POST /api/rooms/:id/reactions {messageId,key}`：校验目标消息，以人类身份发 reaction。
- `DELETE /api/rooms/:id/reactions/:eventId`：只能 redact 自己的 reaction。
- Agent：prompt recent 消息带 event id；agent 可回复 `REACT: <messageId> <emoji>`，Gateway 校验目标后以 agent 身份 sendReaction，不产生聊天消息。
- UI：
  - 消息悬浮 👍 按钮；已点赞后点击撤销（调用 redact）。
  - 气泡下显示 emoji + count chip；自己的 chip 可点击撤销。

## 验证

- script-peer DM 发一条消息，`POST reactions` 200；
- `GET messages?limit=20` 的 `reactions[eventId]` 返回 `[{id,key:"👍",sender:"@kudo"}]`；
- `DELETE reactions/:id` 200，再次 GET 该消息 reactions 为空。
- lint/build 通过；43 tests。

## 边界

- 只有 👍 快捷按钮；没有 emoji picker/自定义 key（API 支持 key）。
- 只能撤销自己的 👍；没有 emoji picker/多 key UI；redact 后本地列表靠下次轮询刷新。
- Agent 只能通过 `REACT:` 标记反应；没有工具 schema/自动选择；未做 E2E（只测了 parseReply）。
- Reaction 事件占分页条数，可能让一页文本消息少于 limit。
- 没有按 reaction 搜索/通知；thread 面板未做。
