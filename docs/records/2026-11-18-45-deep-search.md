# 2026-11-18-45 深搜历史

- 记录时间：2026-11-18。
- 目标：C 轨道——搜索不再只看每房间最近 100 条，给一个显式的“深搜”选项。
- 关联：[13 MVP 架构](../13-mvp-architecture.md) · [记录 39 分页](2026-11-18-39-history-pagination.md)

## 实现

- `GET /api/search?q=&pages=N&offset=&limit=`：`pages` 1–5，每个房间用 Matrix end token 连续翻页，最多 500 条；结果按时间排序后用 offset/limit 分页（limit≤50），返回 total/hasMore。
- SearchView 增加「深搜历史」checkbox；切换后自动重搜；显示扫描范围/命中总数；底部「加载更多」追加结果。
- 普通搜索仍默认 1 页（100 条），保持速度。

## 验证

- `q=收到&pages=1/5` 都返回 19 条；`q=a&pages=5` total=80，offset=0 limit=50 返回 50/hasMore，offset=50 limit=50 返回 30/hasMore=false，两页无重叠。
- lint/build 通过；43 tests。

## 边界

- 有一次请求扫完的 offset/limit 分页（每次重扫），不是高效 cursor；总量受 500 条/房间限制。
- 深搜按房间顺序扫，房间多时慢；没有超时/取消。
- 仍只搜 main thread 文本消息；不含 thread 回复、媒体文件名、reaction。
- 结果按时间排序，不按相关度；没有摘要/命中上下文。
